## 一、游戏概述

### 1.1 一句话概念

> 在哥特古堡中扮演吸血鬼猎人，通过击杀怪物潮获取经验，组合武器与被动道具构建独特 Build，在 25 波攻势中生存并击败吸血鬼领主。

### 1.2 核心体验支柱

| 支柱 | 描述 | 设计目标 |
|------|------|---------|
| **爽快清屏** | 武器组合产生连锁反应，大量敌人同时被消灭 | 单帧击杀数可达 20+ |
| **Build 深度** | 9 武器 × 11 被动 × 2 角色 = 数百种有效组合 | 每种组合有独特手感 |
| **渐进压力** | 敌人数量/强度随波次指数增长，迫使玩家优化 Build | 波次 20+ 仍有挑战性 |
| **风险决策** | 升级三选一需要权衡即时战力与长期收益 | 选择错误可能导致失败 |
| ** Meta 成长** | 血晶永久升级让每局失败都有价值 | 10 局内可解锁全部基础内容 |

### 1.3 与竞品差异化（2026-11 修订，依据 `docs/reference-deconstruction.md`）

| 竞品 | 它的核心答案 | 我们的差异 |
|------|-------------|-----------|
| Vampire Survivors | 30 分钟单图，武器满级 + 被动 + 宝箱＝进化 | 我们用**房间推进**切片时间（3 层 × 5-7 间），每层有自己的敌人池与 Boss；进化从"纯数值"改成"**换玩法**" |
| Brotato | 20 波 + 波间商店，6 武器槽，属性互相惩罚 | 我们**不做 6 武器槽对拼**，改成 4 槽 + 商店房（局内金币），把"取舍"从商店搬到房间路线选择上 |
| 20 Minutes Till Dawn | 手动瞄准 + 弹匣节奏 | 我们保留**手动瞄准**，但**不做弹匣**——用"武器槽 + 进化"代替节奏压力，降低操作门槛 |
| Halls of Torment | 前摇可读（地面紫色标记）、装备带回地表 | 我们借鉴前摇可读性，**不做**它的双轨 Meta（评论公认系统过多） |

**我们的真正差异点（写进 Pillar，不写在对比表里当口号）**：
1. **垂直推进**：不是"在地图里活 30 分钟"，是"打穿三层地下城"。层级 = 叙事进度条。
2. **Boss 是关卡的门，不是计时器的彩蛋**：每层最后一间必是 Boss，Boss 形态随层变化。
3. **低操作、高构建**：只有 WASD + 瞄准，复杂度全部压在升级决策上。

## 二、核心循环

### 2.1 单局循环 (Run Loop)

```
开始游戏
    ↓
选择角色 → 进入房间 1
    ↓
┌─────────────────────────────┐
│  战斗阶段 (30秒/波)          │
│  - 击杀敌人获取经验宝石       │
│  - 拾取经验升级              │
│  - 三选一强化 (武器/被动/属性) │
│  - 清场后开启传送门           │
└─────────────────────────────┘
    ↓
进入下一房间 ←→ 特殊房间 (商店/宝箱/休息)
    ↓
每 5 房触发 Boss 房
    ↓
击败 Boss → 进入下一层 (难度提升)
    ↓
玩家死亡 或 击败最终 Boss → 结算
    ↓
获得血晶 → 永久升级/解锁角色 → 开始新一局
```

### 2.2 分钟级循环 (Moment-to-Moment)

```
0-3秒:   观察敌人位置，决定移动方向
3-10秒:  集中火力击杀高威胁目标 (冲锋怪/远程怪)
10-20秒: 拾取经验宝石，注意躲避弹幕
20-30秒: 清场收尾，准备升级选择
```

### 2.3 设计约束

- **混合瞄准**：所有武器默认自动开火；基础枪械（手枪 / 散弹枪 / 火焰喷射器）朝鼠标方向射击，无需按键；
  追踪类武器（魔法书 / 飞刀 / 十字弩 / 圣光杖 / 苦无）自动索敌。
  玩家永远只需要 WASD + 鼠标位置，没有装填、没有技能键。
- **有限控制**：WASD 移动 + 鼠标瞄准，无其他操作。
- **暂停决策**：升级时游戏暂停，给玩家思考时间。
- **不可逆选择**：升级选择后不可撤销，增加决策重量（重抽/跳过属于额外资源，另算）。
- **弹道必须可读**：既然玩家要瞄，弹道就不能含糊。所有弹丸统一走"亮芯 + 光晕 + 加色混合"
  （`scripts/core/projectile_visuals.gd`），视觉尺寸可以大于碰撞体——看着大，判定不吃亏。

## 三、数值框架

### 3.1 设计原则

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **可控成长** | 玩家强度线性/对数增长，非指数 | 多武器收益递减，进化倍率上限 |
| **压力递增** | 敌人强度指数增长，迫使持续优化 | 波次 HP 系数 1.1^n |
| **防御递减** | 防御属性收益递减，避免无敌 | 护甲百分比减伤，闪避/吸血递减 |
| **时间目标** | 单局 15-25 分钟 | 25 波 + 5 Boss，每波 30s |

### 3.2 玩家基础属性

| 属性 | 基础值 | 成长方式 | 上限 |
|------|--------|---------|------|
| 最大生命 (HP) | 100 | 升级 +20，永久升级 +10/级 | 无硬上限，软上限 ~300 |
| 移动速度 | 200 | 升级 +15%，永久升级 +5%/级 | ~400 |
| 基础伤害倍率 | 1.0 | 升级 +20%，永久升级 +5%/级 | ~3.0 |
| 护甲 | 0 | 升级 +5，永久升级 +3/级 | 减伤上限 75% |
| 拾取范围 | 100 | 升级 +30，磁铁被动 | ~400 |
| 暴击几率 | 0% | 四叶草被动 | 上限 40% |
| 暴击伤害 | 200% | 固定 | 200% |
| 闪避几率 | 0% | 影子披风被动 | 上限 25% |

### 3.3 经验与升级曲线

```gdscript
# 升级所需经验公式
func get_xp_required(level: int) -> int:
    return 20 + (level - 1) * 12 + int(pow(level - 1, 1.5))

# 示例:
# Lv1→2:   20 XP    (击杀 4 只吸血鬼)
# Lv2→3:   33 XP    (击杀 6-7 只吸血鬼)
# Lv3→4:   48 XP
# Lv5→6:   80 XP
# Lv10→11: 220 XP
# Lv20→21: 820 XP
```

| 等级 | 累计经验 | 预计波次 | 武器数量 |
|------|---------|---------|---------|
| 1 | 0 | 1 | 1 |
| 5 | ~200 | 3-4 | 2-3 |
| 10 | ~800 | 7-8 | 4-5 |
| 15 | ~2000 | 12-13 | 6-7 |
| 20 | ~4500 | 18-19 | 8 |
| 25 | ~9000 | 25 | 8+进化 |

### 3.4 敌人强度公式

```gdscript
# ⚠ 2026-11-08 以代码为准重写：旧版这里写的是"1-10 波 +10% / 11-20 波 +15% / 21+ 复利"，
# 那是重构前的分段公式，实际代码已统一成线性。改数值请直接看 game_config.gd。

# 敌人 HP 随波次增长：线性，每波绝对增量恒定
func get_enemy_hp_multiplier(wave: int) -> float:
    return 1.0 + (wave - 1) * ENEMY_HP_LINEAR_PER_WAVE   # 0.12

# 敌人伤害随波次增长：线性
func get_enemy_damage_multiplier(wave: int) -> float:
    return 1.0 + (wave - 1) * ENEMY_DAMAGE_PER_WAVE

# 再叠三层修正（详见附录 C.1）
#   楼层台阶   floor_hp = [1.0, 1.40, 1.85][floor-1]
#   等级橡皮筋 min(1 + (level-3)*0.03, 2.0)
#   DPS 软因子 clamp((实际DPS/该等级期望)^0.35, 0.85, 1.55)
```

**为什么从复利改线性**：复利下第 12 波是 ×3.3，但玩家在同一时期只能感受到"这一间房比上一间厚一点点"。
线性让每过一间房的"变厚"幅度等量，楼层台阶专门负责"下潜"的段落感——
段落的陡峭交给楼层，房间内部保持可预测（试玩反馈「血量不线性」的直接修法）。

## 五、武器系统

数值以 `scripts/weapons/weapon_data.gd` 的分轴表为准。这里不再写「每级都加伤害」的全局公式。

### 5.1 两条结局

- **变种**：2 到 5 级每级只改表里那一个轴。卡片文案和这一级实际变化的字段一致。满级伤害、间隔、弹道和旧公式的满级结算对齐；飞刀把一部分穿透换成 1 次弹墙。
- **宝箱进化**：武器满级，加上对应被动至少 1 级，再开宝箱。只养一把武器走这条。
- **融合**：两把不同武器都满级、都没进化过，升级三选一里出现一张卡。选了之后主武器留下并改行为，副武器离槽，本局只此一次。可以不选。手枪不进融合，它的结局仍是宝箱进化「神圣双管」。

没有变种表的武器不能进升级池。新武器先做普通成长和宝箱进化，不进融合。

### 5.2 武器与满级终点

| 武器 | 1 级 | 满级时和 1 级不同的部分 |
|------|------|------------------------|
| 手枪 | 伤害 4.0，间隔 0.25，弹道 1 | 弹道 3，间隔 0.19，伤害 6.4 |

### 6.3 收益递减公式

```gdscript
func get_scaled_value() -> float:
    var total = base_value
    for i in range(1, current_level):
        total += value_per_level * pow(decay_factor, i - 1)
    return total

# 示例: 影子披风 (decay=0.8)
# Lv1: 5%
# Lv2: 5% + 3% = 8%
# Lv3: 5% + 3% + 2.4% = 10.4%
# Lv4: 5% + 3% + 2.4% + 1.92% = 12.32%
# Lv5: 5% + 3% + 2.4% + 1.92% + 1.54% = 13.86%
```

#### HP 缩放公式

```gdscript
func get_boss_hp(base_hp: float, boss_tier: int) -> float:
    # boss_tier: 1=波次5, 2=波次10, 3=波次15, 4=波次20, 5=波次25
    return base_hp * pow(2.0, boss_tier - 1)
    # 波5: 800, 波10: 1600, 波15: 3200, 波20: 6400, 波25: 12800
```

### 8.2 Boss 形态表（已实现）

三个楼层 Boss 共用 `vampire_lord.tscn` 与同一套攻击状态机，由 `boss_variant` 参数驱动差异，避免为每个 Boss 单独维护一套脚本。

| 层 | Boss | tier | 基础 HP | 核心差异 | 光环色 |
|---|------|------|--------|---------|--------|
| 1 | 吸血鬼领主 | 1 | 650 | 基准形态：8 发弹幕、CD 2.5s、50% 进狂暴 | 暗红 |
| 2 | 血族亲王 | 2 | 1600 | 移速 75、10 发弹幕、CD 2.2s、55% 进狂暴、体型 1.1× | 紫 |
| 3 | 血族女王 · 塞拉菲娜 | 3 | 3200 | 移速 85、12 发弹幕、CD 2.0s、60% 进狂暴、体型 1.2×、召唤 5 只 | 金 |

三种形态共用同一个三阶段循环（普通 → 狂暴 → 绝望），阶段增益按 `boss_variant` 线性叠加：

- 狂暴：`move_speed = 88 + variant*10`，`base_contact_damage = 30 + variant*4`，`barrage_count = 12 + variant*2`

> **血量只由 tier 决定，不叠加层倍率与波次倍率。** 早期版本同时乘了 tier、层、波次三个系数，导致第 3 层 Boss 血量失控、战斗拖到 40 秒以上。现在 Boss 血量查 `GameConfig.BOSS_HP_TIERS`，实测 TTK 稳定在 17–22 秒。

## 九、关卡与房间系统

### 9.1 房间类型与层内节奏

每层的房间序列在**进入该层时一次性生成**，保证节奏可控，不靠纯随机堆叠。

| 类型 | 层内位置 | 功能 |
|------|---------|------|
| **战斗房** | 第 1 间固定为战斗房，其余填充 | 一波敌人，清场后开门 |
| **特殊房** | 第 2 间 ~ Boss 房前一间，每层固定 1–2 个 | 商店 / 宝箱 / 休息，权重 45 / 35 / 20 |
| **Boss 房** | 该层最后一间 | 该层 Boss |

设计约束：

- 第 1 间必须是战斗房，避免开局就被商店/对话打断战斗节奏
- 每层至少 1 个特殊房，保证补给不至于断档
- 特殊房数量固定而非随机，玩家能建立稳定的节奏预期

| 1 | 血月回廊 | 6 | 4 | 1.00× | 1.00× | 吸血鬼领主 (650 HP) |
| 2 | 骸骨墓穴 | 7 | 4 | 1.40× | 1.18× | 血族亲王 (1600 HP) |
| 3 | 血之王座 | 7 | 4 | 1.85× | 1.40× | 血族女王 (3200 HP) |

合计 20 间房、12 个战斗波次，单局约 12–18 分钟。

**层推进规则**

1. 击败该层 Boss → 播放「第 N 层 · 已肃清」横幅
2. 发放层奖励：恢复 50% 生命 + 血晶（第 1/2/3 层分别为 30 / 60 / 120）
3. 播放「第 N+1 层」入场横幅（层名 + 英文副标题 + 氛围提示）
4. 自动进入下一层第 1 间房，启动新一波
5. 第 3 层 Boss 击败 → 播放「地下城已征服」→ 胜利结算

**难度叠加方式**

```
敌人最终 HP = base_hp × 波次系数(1 + (wave-1)×0.12) × 等级橡皮筋 × 层倍率 × DPS 软因子
```

波次计数**全局累加，不随层重置**。层倍率是在波次曲线之上的额外台阶，用来制造"下潜一段就更凶"的体感。两套系数叠加后必须重新验算 TTK —— 这也是每层房间数定为 6/7/7 而不是 5 的原因：5 间房里只有 2–3 间是战斗房，玩家到第 3 层 Boss 时仅第 8 波，DPS 跟不上 3200 血的女王，Boss 战会被拖到 40 秒以上。

**验算工具**：`tools/dungeon_test.gd` 会跑 200 次完整流程校验房间结构，并输出三层 Boss / 杂兵的 TTK 表。当前结果：

| 层 | Boss HP | 到达波次 | 玩家 DPS | Boss TTK |
|---|--------|---------|---------|---------|
| 1 | 650 | 4 | 36.5 | 17.8s |
| 2 | 1600 | 8 | 74.3 | 21.5s |
| 3 | 3200 | 12 | 188.9 | 16.9s |

|------|------|---------|

### 10.1 血晶经济

#### 获取公式

```gdscript
func calculate_blood_crystals(stats: Dictionary) -> int:
    var base: int = 0
    base += stats.get("kills", 0) / 8        # 每8杀1血晶 (降低)
    base += stats.get("rooms", 0) * 2        # 每房间2血晶 (降低)
    base += stats.get("wave", 0) * 3         # 每波次3血晶 (提高)
    base += stats.get("level", 1) * 3        # 每等级3血晶 (降低)
    base += stats.get("boss_kills", 0) * 50  # 每Boss50血晶 (新增)
    return int(base * (1.0 + get_bonus_multiplier()))
```

## 十四、平衡性设计原则

### 14.1 数值设计铁律

| 原则 | 说明 | 违反后果 |
|------|------|---------|
| **击杀时间恒定** | 任何阶段击杀基础敌人 0.3-1.0s | 前期挫败/后期无聊 |
| **防御收益递减** | 任何防御属性不得超过 75% 减伤 | 后期无敌 |
| **DPS 增长可控** | 玩家 DPS 增长不超过对数曲线 | 数值崩塌 |
| **Boss 战时长** | Boss 战必须在 15-25s 区间 | 过短无聊/过长挫败 |
| **选择有意义** | 任何升级选项在特定 Build 下都有价值 | 存在最优解 |

### 14.2 常见陷阱与规避

| 陷阱 | 规避方案 |
|------|---------|
| 护甲堆叠无敌 | 百分比减伤，上限 75% |
| 闪避 100% | 递减公式，上限 25% |
| 吸血无限 | 触发几率递减，上限 28% |
| 多武器指数增长 | 第 N 武器伤害 × 0.9^(N-1) |

## 十六、竞品拆解与迭代路线（2026-11）

> 完整调研过程、代码级观察与来源链接见 `docs/reference-deconstruction.md`。
> 本章只保留**已经决定要做的**和**明确不做的**，避免文档变成读后感。

### 16.1 采纳原则

1. 只抄**已经在本作代码里能低成本验证**的机制，不抄需要重写架构的。
2. 抄"结构"，不抄"数值"。别人的 5%/10% 是它自己曲线上的点，我们的曲线在附录 C。
3. 每个采纳项必须有**可观测的验收标准**，否则不进路线图。

### 16.2 P0：局内金币 + 真·商店房（✅ 已实现 2026-11-08）

**问题**：原来 `_enter_shop_room()` 只回血 30% 并开传送门，玩家整局没有"花钱"这件事，
所有取舍都压在三选一上，三选一又完全随机 → 玩家感觉"变强是运气"。

**参考**：Brotato 的波间商店（武器/道具/重抽/锁定），VS 的宝箱。

| 参数 | 实现值 | 说明 |
|------|------|------|
| 货币名 | 银币 `player.silver` | 局内清零，与血晶严格分离 |
| 掉落 | 普通怪 1 / 精英 5 / Boss 12 | 同点 30px 内自动合并金额，避免节点爆炸 |
| 拾取 | 吸附半径 110（+拾取范围一半），12s 未拾自动收取 | 残局不用跑回去捡钱 |
| 货架 | 4 格（武器 26-34 / 被动 20-26 / 消耗品 10-22） | 数据在 `scripts/core/item_catalog.gd` |
| 重抽 | 8 → 12 → 16（同一间内递增） | 随机性可以用钱谈判 |
| 锁定 | 免费，重抽时保留该格 | 制造"为未来省钱"的决策 |
| 入场补给 | 回血 20% | 避免"没钱＝白跑一间房" |
| 武器槽满时 | 只卖已拥有的武器（重复购买＝升级） | 与三选一同样的防无限扩槽规则 |
| 暂停 | 打开商店暂停世界 | 与升级界面一致，可以慢慢挑 |

**实现位置**：`scripts/ui/room_shop.gd`（UI 全代码构建）、`scripts/player/silver_coin.gd`、
`scripts/core/item_catalog.gd`（与三选一共用的物品目录）、`main.gd::_enter_shop_room()`

**验证**：`tools/shop_test.gd`（银币接口 / HUD 同步 / 拾取 / 开合暂停 / 重抽扣费 / 锁定保留 /
购买结算 21 项断言）、`tools/run_dungeon_smoke.gd`（商店房弹出 → 关闭 → 传送门生成）

### 16.3 P0：三选一加"重抽 / 跳过"（✅ 已实现 2026-11-08）

- 每局 3 次免费重抽，用完后 10 银币/次。
- 跳过：+15 银币（不直接给血晶，避免刷）。
- 目的：让"运气差"有出口，同时把随机性变成一种可支付的资源。

**实现**：`scripts/ui/upgrade_ui.gd` 底部按钮行（重抽 / 跳过 + 状态提示），
快捷键 `R` 重抽、`Tab` 跳过；`GameConfig.REROLL_FREE_COUNT / REROLL_SILVER_COST / SKIP_SILVER_REWARD`。

顺带修了两个隐性 bug：

| 问题 | 后果 | 修法 |
|---|---|---|
| 重抽只 `queue_free` 旧卡 | 旧卡到帧末才移除，重抽瞬间 6 张卡叠在容器里 | 先 `remove_child` 再 `queue_free` |
| 一次吃多颗宝石连发多次 `level_up` | 后一次升级把前一次的选项直接顶掉，玩家白丢升级 | `main.gd` 加 `_pending_upgrades` 队列，关窗后依次弹出 |

**验证**：`tools/phase17_test.gd`（免费次数 / 扣费 / 拒付 / 跳过补偿 / 队列连弹）

### 16.5 P1：打击感三件套（✅ 已实现 2026-11-08）

| 项 | 参数 | 实现位置 |
|---|---|---|
| 枪口闪光 | 60ms 锥形亮片，弹丸同色，加色混合，**每次开火一次**（不是每颗子弹） | `vfx_manager.spawn_muzzle_flash()` |
| 命中冻帧 | 0.05s，仅冻结受击者（Boss 不冻） | `enemy_base._apply_hit_freeze()` |

### 16.6 P2：Boss / 精英重击的地面标记（✅ 已实现 2026-11-08）

原来 `_telegraph_attack()` 只有本体闪红 + 一圈警告环，玩家看不出"打到哪里"。
参考 Halls of Torment：地面留一个逐渐填满的圆环，标记即将落点。

`vfx.spawn_ground_marker(pos, radius, color, duration)`：35% 缩放长到 100%，
落点瞬间描边转白并淡出。已接入：

| 攻击 | 标记 | 前摇 |
|---|---|---|
| Boss 冲刺 | 落点 82px 红圈 | 0.45s（新增 `DASH_WINDUP` 状态，之前是瞬发无前摇） |
| Boss 新星 | 本体 150px 紫圈 | 0.55s（新增 `NOVA_WINDUP` 状态，之前是瞬发） |

**注意**：光有标记没有前摇等于没有——原来是"闪一下就冲"，玩家看见了也躲不掉，
所以这次把冲刺和新星都改成了"先亮圈、再出手"。

### 16.7 试玩反馈修正（✅ 已实现 2026-11-08 第二轮）

第二轮试玩提了 4 条，逐条对应的设计结论：

| 反馈 | 根因 | 结论（已成规范） |
|---|---|---|
| 开火时人物"轻微回退" | 上一版把后坐做成**真实速度**加进 `velocity`，每枪约 3px，多武器连射会叠加 | **打击感只能做视觉，不能动坐标**。开火反馈改为精灵挤压 6% / 0.08s 回弹；`apply_recoil()` 接口保留但零位移 |
| 不知道身上有没有护盾 | ① 拾取后要空等 30s 冷却才出盾 ② 视觉只有 `sprite.modulate` 循环闪蓝，和受击闪红抢同一属性 ③ HUD 无任何提示 | **状态类 buff 必须三处同时可见**：角色身上的光环 + HUD 文字/进度 + 拾取瞬间立即生效。且光环必须是独立节点（环心镂空），不能用 modulate 冒充 |
| 重抽 / 金币已可见 | — | 保持 |
| 武器 / 技能等级看不见 | 三选一卡片只有名字 + 一句定位文案，选完不知道升到 Lv.几；HUD 完全没有 Build 一览 | **任何可升级项都要显示 `Lv.N → Lv.N+1`**，新获得标 `NEW`，属性卡显示"现在 → 选完"的数值；HUD 常驻武器/被动面板 |

顺带修掉的三个实际问题：

1. `_grant_shield()` 里那个 `create_tween().set_loops()` 从来没有被 kill 过——护盾碎了人物还会一直闪蓝，直到本局结束。
2. 武器满级后仍会出现在三选一里，卡面写成 `Lv.5 → Lv.5`（废卡）。现在满级武器直接过滤。
3. `weapon_manager.add_weapon(null)` 会在 `existing.weapon_id` 上崩（`ItemCatalog` 里没有起始手枪 `pistol`）。已加空值挡板。

**验证**：`tools/feedback_v2_test.gd`（47 项断言）+ `tools/hud_shot.gd`（截图核对布局）。

### 16.9 精英词缀系统（✅ 已实现 2026-11-08）

**问题**：怪只会"更多、更肉"，玩家在第 3 局就看完了全部变化。
直觉答案是"再加 10 种敌人"，但那是线性增长（每加一种，程序/美术/平衡各付一次成本）。

**做法**：让**现有 8 种敌人随机长词缀**。同样的骷髅射手，带血盾时逼你先拆盾、
带冲锋时逼你侧移、带急速时逼你优先集火——变的是"威胁类型"，不是贴图。

| 词缀 | 表现 | 玩家应对 | 关键实现 |
|---|---|---|---|
| 血盾 | 蓝色光环，开场带一层盾 | 先拆盾，破盾前不掉血 | 护盾**直接计入 max_hp**，见下 |
| 冲锋 | 红色光环 + 地面预警圈 | 前摇 0.6s 内离开落点 | 剥夺宿主物理帧，自己驱动突进 |
| 裂变 | 紫色光环 | 杀死后会变两只小的，注意清场 | 监听 `enemy_died`，子体禁止继承词缀 |
| 急速 | 金色光环 | 优先击杀，否则一圈小怪都变快 | 每 0.4s 给 150px 内敌人刷新加速 |

**统一加成**（`GameConfig`）：血量 ×1.35、接触伤害 ×1.20、银币 ×4、经验 ×2、体型 ×1.22。
出现概率按层递增：第 1/2/3 层 8% / 14% / 18%。Boss 不参与（Boss 有自己的三形态）。

**词缀池按层解禁**（`ELITE_AFFIX_POOL_BY_FLOOR`）：第 1 层**只出「急速」**，
血盾 / 冲锋 / 裂变从第 2 层才开始。原因是血盾为「×1.35 血 ×1.45 盾」的叠乘，
旧版 10% 概率下一间房就有 3 只带盾怪，第一间房直接变成拆盾考试——
试玩反馈原话「怎么第一关小怪就有护盾啊」。急速不加血量，只把周围小怪催快，
适合作为词缀系统的教学出场。

**四个实现取舍**（都是踩过坑的结论）：

| 取舍 | 理由 |
|---|---|
| 护盾不是独立伤害拦截，而是 `max_hp += 盾量` | 一半敌人自己覆写了 `take_damage`（石像鬼/自爆鬼/亲王/精英），拦截式护盾要改 4 处且以后每加一种敌人改一次。加成 HP 则"任何伤害路径"天然先吃盾 |
| 词缀挂在**子节点**控制器上，不写进敌人基类 | 吸血鬼、狼人、石像鬼、射手都覆写了 `_physics_process`，基类钩子对它们完全不生效 |
| 控制器必须 `extends Node2D` | `Node` 不是 CanvasItem，子节点不继承变换——光环和图标会全部画在世界原点（**这是实机截图才发现的**） |
| 冲锋用 `host.set_physics_process(false)` 接管 | 前摇要"原地不动"，只设 `velocity = 0` 拦不住那些自己调 `move_and_speed()` 的敌人；收招/被冻结时必须把物理帧还回去，否则这只怪会僵到死 |

**顺带统一**：`elite_vampire.gd` 原本有一套私有 `enum Affix { SPEED, ARMOR, SPLIT }`
和自绘的 modulate 循环（和受击闪白抢属性）。现已全部并入通用词缀，精英吸血鬼
= 高体质敌人 + 必带词缀。

**验证**：`tools/elite_affix_test.gd`（63 项断言：词缀随机/逐层概率/四项加成/
护盾当血用/裂变不递归/冲锋前摇-突进-收招-物理帧归还/急速加速与恢复/光环跟随敌人/
双词缀统一加成只结算一次与第二血盾行为）。

### 16.10 第二轮调研：还值得抄什么（未实现，按性价比排序）

调研全文见 `docs/reference-deconstruction.md` §10。结论按"每单位工作量带来的玩法变化"排队：

### 16.11 Roguelite 决策层：放逐 / 契约 / 软挂钩 / 临时增益（✅ 已实现 2026-11-08 第四轮）

上一批解决的是"打起来爽不爽"，这一批解决的是**"局内有没有真正的选择"**。
四项都指向同一个诊断：玩家在局内能做的决策太少——升级靠随机、休息房白送血、
难度只看等级、战斗房只有输出循环。

#### 16.11.1 放逐 Banish（每局 3 次）

- 入口：三选一界面 footer 第三个按钮（键盘 `B`）。进入后卡片整块染红、角标换成"放逐"，
  点哪张就从**本局**选池永久移除该项。
- **不消耗重抽次数**，并且自带一次免费刷新。理由：如果 ban 也要花重抽，
  玩家会在"该 ban 还是该 reroll"之间做成本核算，而 ban 的乐趣恰恰在于无脑执行。
- 只影响三选一池，**商店仍可买到**被 ban 的项。否则 ban 会同时变成经济操作，
  玩家会为了"不让商店刷出垃圾"而 ban，偏离设计意图。
- 实现：`banished_keys` 存 `"type:id"`，`_get_available_options()` 在最后一次遍历里统一过滤
  （不在三个 append 点各抄一遍，否则加第四类选项时必然漏一处）。

#### 16.11.2 深渊契约（休息房 → 血之祭坛）

原来是"进房回 50% 然后开门"，零决策。现在二选一：

| 选项 | 效果 |
|---|---|
| 🕯 安息 | 恢复 50% 最大生命（稳妥） |
| 🩸 缔约 | **本层**最大生命 -20% → 本层敌人 +20% 数量、银币与经验 +30% |

三个关键取舍：

1. **惩罚只挂本层，层末归还**。整局 -20% 能被 3 间休息房叠到 -48%，
   纯数值惩罚会把一局直接玩死；本层扣、层末还，玩家每层重做一次决策，
   赌的是"这层能不能用 +30% 掉落赚回来"。
2. **同层只允许缔约一次**。否则连开两间休息房时，第二次不点就亏，等于逼玩家必须连点——
   那就不是选择了。
3. **残血禁选**（扣完上限后当前血必须仍高于新上限的 30%）。不设这道闸门，
   残血玩家点契约等于自己选了自杀，非常糟糕的体验。

实现细节：
- 玩家新增 `change_max_hp()`：扣上限时 clamp 当前血，还上限时**不**凭空补血
  （否则契约变成零成本血包）。
- 数量倍率按"应发总量 vs 实发总量"对齐，不用 ceil（+50% 而非 +20%），
  也不用"每次留小数余量"（浮点误差跨批累积，10 批实测少 1 只）。
- 掉落取整按小数部分概率进位，否则 1 银币 ×1.3 永远给 1，"倍率没生效"。

#### 16.11.3 武器强度软挂钩（DPS 自适应）

原来的橡皮筋只看等级（每级 +3% 血，上限 2 倍）。但等级不等于强度：
同样 15 级，"进化武器 + 满级被动"和"五张属性卡"的实际 DPS 能差 3 倍。

```
ratio = 实际DPS / (16 × 1.20^(等级-1))
soft  = clamp(ratio^0.35, 0.85, 1.55)      # 每波 lerp 0.5 靠拢
```

- **只做软修正**：DPS 超模 2 倍，敌人只硬 27%。硬对齐会抹掉构筑成长的快感，
  那是 Roguelite 最不能碰的东西。
- 实际 DPS 用 `weapon_manager.estimate_run_dps()` **估算**，不去统计真实伤害：
  `take_damage` 有 4 个子类覆写，打点必然漏，而漏掉的伤害会让"玩家明明很强却被判成弱"。
- 1 级基准 16 = 手枪 4 伤害 / 0.25 秒，与实现值严格对齐，保证开局不被动过手脚。
- HUD Build 面板底部显示"敌方强度 ×N.NN"（仅在偏离 1.0 时出现）。
  藏起来只会让玩家怀疑数值崩了。

#### 16.11.4 战斗内临时增益

| 增益 | 效果 |
|---|---|
| 血 血露 | 立即恢复 25% 最大生命 |
| 狂 狂暴 | 8 秒内伤害 ×1.5（玩家身上带橙色光晕） |
| 磁 磁力 | 立刻把 900px 内的经验与银币拉到脚边 |

- **定时刷新（24s）而非击杀掉落**：击杀掉落会奖励已经很强的玩家（杀得快→掉得多→更强），
  是正反馈雪球；定时供给是中立的，弱构筑反而更需要它。
- 位置刻意放玩家 **200~360px**（约半个屏幕）：太近等于白送，太远玩家懒得去。
- 16 秒存活上限，**超时不自动拾取**——不然就没有"要不要过去"的决策了。
- 图标用中文字（血/狂/磁）而不是 emoji：项目字体 NotoSansCJKsc 不含 emoji 字形，
  emoji 在本机渲染成空白方块。**这个坑只有截图能看出来，无头测试永远发现不了。**

**验证**：`tools/roguelite_ops_test.gd`（66 项断言），
截图核对 `tools/pact_shot.gd` / `tools/powerup_shot.gd`。

### 16.12 远程火力爬坡 + 经验拾取修复（✅ 已实现 2026-11-08 第六轮）

试玩反馈两条：「小怪投射物太多了，需要到后期慢慢增多才合理」「经验依旧有捡不到的」。

#### 16.12.1 远程敌人三层爬坡

问题不是"远程敌人不该存在"，而是**第 1 层第一间房就可能被三四条弹道同时追着跑**：
第 1 层敌人池 5 种里有骷髅射手，池子里有就可能被选中，2 秒冷却 + 20% 三连发。

| 控制层 | 第 1 层 | 第 2 层 | 第 3 层 |
|---|---|---|---|
| 逐层解禁（本层已清房间数 ≥） | 4 | 2 | 1 |
| 开火冷却倍率 | ×1.7（2.0s → 3.4s） | ×1.25 | ×1.0 |
| 同屏弹道上限 | 3 | 7 | 12 |
| 三连发概率 | 0% | 18% | 30% |

- **用"同屏上限"而不是"减伤害"**：玩家抱怨的是屏幕被弹幕糊住、没有走位缝隙，
  那是视觉与空间问题。只改伤害的话弹幕照样糊屏，只是没那么痛。
- **按本层已清房间数解禁，而不是按波次**：一间战斗房只打一波，
  波次号在每间房都会重置成 1，用它做爬坡等于永远不爬。
- 被上限拦下的射手只等 **0.35 秒**重试，不是彻底哑火——否则会出现
  "射手站着不动当靶子"的反效果。
- 法师（第 2 层起）走同一套上限，并顺手删掉了每次施法的 `print`。

#### 16.12.2 经验拾取：四个叠加根因

| # | 根因 | 表现 | 修法 |
|---|---|---|---|
| 1 | `"pickup_range" in player` 判断的字段不存在（真实字段是 `pickup_range_bonus`） | **磁力戒指与"拾取范围 +30"升级完全空转** | 改读 `pickup_range_bonus`；玩家侧磁力加成改为"只补差额"，不再覆盖猎人自带 +20 |
| 2 | 拾取必须在 `is_attracted` 为真时才判定 | 贴身站住也不捡 | 距离 < 16px 无条件拾取 |
| 3 | 吸引速度固定 320，而玩家跑速 200 起、还能叠移速 | 玩家跑动时宝石追不上，一路跟着永远吃不到 | 速度取 `max(320, 玩家速度×1.6+120)` |
| 4 | 掉落点直接用敌人坐标 | 冲锋/击退/自爆把敌人推出墙外，宝石掉进墙里 | 掉落坐标 clamp 到 `get_room_bounds()` 内 |

另外两处体验补齐：

- 基础吸附半径 **88 → 120**（约一个身位）。88 太依赖"擦身而过"，
  偏一点就留在原地——这正是"有时候捡不到"的体感来源。
- 波次结束时 `magnetize_xp_gems()` 让剩余宝石**真的飞向玩家**再入账，
  而不是 `settle_xp_gems()` 那样原地消失。换房时仍用立即结算（房间节点会连宝石一起释放）。

**验证**：`tools/ranged_pressure_test.gd`（28 项断言：三层解禁表、类型抽取、
弹道上限拦截、冷却倍率、吸附半径与 `pickup_range_bonus`、波次磁力回收）、
`tools/xp_pickup_diag.gd`（真实掉落链路 24 枚宝石 + 4 次池化复用的实机诊断）。

### 16.13 第七轮试玩反馈：数量、速度、可视性（✅ 已实现 2026-11-08）

这轮五条反馈里，有**三条其实是同一个病**：场上信息量超过了玩家能处理的上限。
怪太多（扎堆）、来得太快（来不及捡）、看不清（弹道太细）——都是"可读性"问题，
不是"难度"问题。所以本节按"玩家每秒钟要处理多少信息"来组织，而不是按 bug 列表。

| # | 反馈原话 | 根因 | 修法 |
|---|---------|------|------|
| 1 | 「wave4 没有任何东西」 | `wave_label` 只在 `wave_started` 刷新，进宝箱房/商店房时还挂着上一波编号，房间里却空的 | HUD 新增 `set_wave_status()`：波次结束显示「Wave N 已清 · 走传送门」（变暗），进非战斗房显示「宝 箱 / 商 店 / 休 息 / BOSS」 |
| 2 | 「怪初始移动速度有些过快，来不及捡经验」 | 第 1 层只放「急速」词缀，倍率 1.30 把蝙蝠从 140 催到 182，贴着玩家 200 的跑速；宝石又只在 30 秒波次结束那一刻才磁吸 | 急速 1.30 → **1.18**；蝙蝠 140 → **128**；第 1 层精英概率 8% → **5%**；补「清场即磁吸」（见下） |
| 3 | 「自己的投射物太细，很难命中敌人」 | `thickness: 6` 是**整个光晕的直径**，亮芯只占 0.16 → 屏幕上实心部分不到 2px | 亮芯占比 0.16 → **0.30**；武器视觉厚度 5~6 → **8~9**；子弹判定半径 4.0 → **5.5**、飞刀判定 16×4 → **18×6** |
| 4 | 「wave5 起怪扎堆，甚至没地方跑」 | **完全没有同屏上限**：每 1.1~1.3 秒刷一批、每批 3~4 只，一波 30 秒就是 70~90 只；玩家 DPS 清不完，场上越堆越多 | 新增 `ENEMY_ALIVE_CAP_BY_FLOOR = [16, 22, 28]` + 软上限慢补 |
| 5 | 「攻击力提升没有具体数值，可以有体感提升」 | 满级后的「伤害提升」补给卡只有一句「攻击力+10%（本局）」，没有"现在多少 → 加完多少"；选完也没有任何屏幕反馈 | `_basic_preview()` 生成「攻击 ×1.30 → ×1.40」；选完走 `hud.show_toast()` 飘一行 |

#### 16.13.1 同屏上限：为什么是 16 / 22 / 28

这是这轮唯一一个**结构性**改动，值得单独说明。

**问题的本质是"数量曲线"和"击杀速度"脱钩。**
之前只控制"刷多快"，不控制"场上留多少"。刷怪是定时器驱动，击杀是玩家 DPS 驱动——
两者互不相干，一旦 DPS 落后于刷新速度，差额就永久累积在场地上，30 秒后就是 70~90 只，
下一间房再叠。这不是"后期变难"，而是**失控**：难度会随玩家失误单调放大，没有回归机制。

**有上限之后**，压力由"同时在场的敌人"决定，而不是"累计刷了多少"：

- 杀得快 → 补得快，压力持续存在（没有"清完就没事干"的空窗）
- 杀得慢 → 不再加码，玩家有余力止损（不会雪崩到动不了）

**为什么数值比同类小两个数量级**：Vampire Survivors 的同屏硬上限在数百量级，
SurvivorsStarterKit（Godot 4.4 / C#，MIT）标称 `MaxEnemies = 200`。差异不在"谁的怪多"，
而在**每个敌人占多少活动面积**：

| | 我们的房间 | VS 类 |
|---|---|---|
| 可活动区域 | 1280×720 ≈ 0.92 M px²（固定小房间） | 1920×1080 屏幕 + 远超一屏的整张地图 |
| 玩家的清场手段 | 单体/小范围投射物为主，靠瞄准 | 大量全屏 AOE、环绕、持续地面效果 |
| 同屏上限折算 | 16 只 ≈ 每只 5.8 万 px²（约 240×240 一格） | 300 只 ≈ 每只 0.9 万 px² |

按"每只敌人可用面积"折算，16 只的房间密度**已经高于** VS 后期。
直接照抄 200/300 会让这个 1280×720 的房间在开局就变成无路可走的肉墙。

**软上限**：距离上限还剩 4 只时，补怪间隔直接 ×2。否则场上将满时每一批都在"填缝"，
玩家刚清出的一条退路会被立刻补上——这仍然是"没地方跑"，只是从"堆满"变成"填满"。

#### 16.13.2 清场即磁吸：1.5 秒的余量

原来 `magnetize_xp_gems()` 只在 30 秒波次计时到点那一刻触发。于是"前 10 秒清完场"的玩家
要面对 20 秒空窗——宝石躺在地上，怪还在刷，去捡就得赌命。这就是「来不及捡经验」。

现在改成：**场上敌人归零且地上还有宝石时，计时 1.5 秒后自动磁吸**。
留 1.5 秒而不是立即吸走，是为了保住"走过去捡"这个决策：
刚好看得见宝石落地、还没来得及决定要不要过去，它就自己飞过来了。

判定用的是**场上真实节点数**而不是 `enemies_alive` 计数器。换房时残留敌人是被 `main`
直接 `queue_free` 的，不走 `_die`，计数器只增不减——一旦虚高，磁吸和同屏上限会同时失效。
所以两处都以 `get_tree().get_nodes_in_group("enemies").size()` 为准（每 0.5 秒采样一次，不逐帧扫组）。

#### 16.13.3 投射物"看着多大就多好打"

一条硬规矩：**视觉实心部分与碰撞判定必须同一量级**。
"看着很粗但判定只有一条线"会让玩家觉得打不中；"看着很细但判定很宽"会让玩家觉得莫名其妙吃到伤害。

| 武器 | 视觉厚度（旧→新） | 亮芯实心宽度 | 判定 |
|------|------------------|-------------|------|
| 手枪 / 默认 | 6 → 9 | 1.9px → 5.4px | 半径 4.0 → 5.5 |
| 霰弹枪 | 6 → 9 | 同上 | 同上 |
| 飞刀 | 5 → 8 | 1.6px → 4.8px | 16×4 → 18×6 |
| 十字弩 | 6 → 9 | 同上 | 同上 |
| 苦无 | 5 → 8 | 同上 | 同上 |

圆形弹（法球/Boss 弹幕）的亮芯占比**刻意没动**：Boss 弹幕的判定半径是独立的，
视觉变粗而判定不变会制造"看着该中却没中"的反向错觉。要改就得两边一起改，那是另一轮的事。

#### 16.13.4 一个数值一致性 bug（顺手挖出来的）

写「补给卡显示具体数值」时发现：卡片预览读的是 `UPGRADE_DAMAGE_MULT`（0.20），
而实际生效写死 `+= 0.1`。也就是**卡片承诺 ×1.20，玩家只拿到 ×1.10**。
这类"显示与实际不一致"比数值偏强偏弱伤得多——玩家会觉得游戏在骗他。
现在两边共用 `GameConfig.BASIC_REWARD_DAMAGE`，并在 `feel_fix_test` 里加了断言：

```
实际生效 ×1.10 与卡片承诺 ×1.10 一致
```

**验证**：`tools/feel_fix_test.gd`（25 项：上限表与越界、实机塞满 16 只后拒绝刷怪、
满员间隔 2.60s、清场磁吸延迟、视觉厚度与判定直径比值、亮芯实心像素、预览与生效一致）。

### 16.14 与同类开源项目的对标（2026-11-08）

用户要求「整体参考开源项目优化」。这里记录**具体抄了什么、没抄什么、为什么**，
避免下次又从头讨论。以下结论来自公开的项目说明与玩法拆解，不是印象。

| 项目 | 它的做法 | 我们的决定 | 理由 |
|------|---------|-----------|------|
| **Vampire Survivors**（商业，玩法标杆） | spawn director 有同屏硬上限（公开拆解普遍提到数百量级），到顶就停止生成，等降到阈值以下再补 | ✅ **抄概念**，数值按房间尺寸重算（16/22/28） | 硬上限解决"越堆越多"的失控，与地图大小无关；但数值不能照抄，见 16.13.1 的面积折算 |
| 同上 | 敌人组成**随游戏时间演化**，而不是固定的"第 N 波刷第 N 种" | ✅ **部分抄**：已有权重池 + 逐层解禁 + 远程按"本层已清房间数"爬坡 | 固定波表会让玩家背表；权重池让每局组成不同，同时保留"某层开始出现某兵种"的可预期性 |
| 同上 | 升级选项数量有硬上限（6 武器 + 6 被动），武器满级 + 特定被动 = 进化 | ✅ 已抄（`MAX_WEAPON_SLOTS` + 宝箱进化事件） | 限制构筑宽度是让"选择"有意义的前提，全拿等于没选择 |
| **SurvivorsStarterKit**（MIT / Godot 4.4 C#） | `MaxEnemies = 200`，敌人组成随时间演化，Jolt 物理；作者实测默认物理在 50 只时撞墙 | ⚠️ **只抄上限思路**，性能方案不适用 | 我们是 2D + 已有的对象池；它的瓶颈在 3D 物理。它"50 只撞墙"是 3D 场景的结论，不能拿来推断 2D |
| **2D Survivors**（开源 / Godot 4 GDScript） | 难度**每 5 秒**升一档、刷怪随之加快；存活 300 秒获胜 | ❌ **不抄** | 连续计时制才有"每 5 秒一档"；我们是房间 + 波次制，节奏单位是房间，照搬会让 30 秒一波内出现 6 次跳档，玩家读不出规律 |
| **Capybara Survivor**（开源 / Godot） | 用**线性回归**拟合玩家得分斜率，每 40 秒调一次难度 | ⚠️ 思路已用等效实现 | 我们的 `DPS 软挂钩`（`17.9`）做的就是同一件事：实测构筑强度 → 修正敌人血量。它用回归、我们用比值+指数压缩，不必引入统计模型 |
| **Brotato**（商业，房间制标杆） | 把长关卡切成 1 分钟小关，关间进商店；经验/金币双轨 | ✅ 已有等效结构（6 房间/层 + 商店房 + 银币） | 房间制天然有"喘口气"的节奏点，这是我们和 VS 类最大的结构差异 |

**没抄但值得记一笔**的两条：

1. **VS 的"中期人群变密、逃跑路线变少"是刻意设计的情绪曲线**，不是失控。
   我们这轮压掉了扎堆，但**中期该有的压迫感不能一起压掉**——
   上限是 16/22/28 逐层递增而不是固定 16，就是为了保住这条曲线。
2. **Brotato 的"1 分钟一关"**：单房间波次时长（30 秒）比它长一倍。
   如果后续觉得单房间节奏拖，第一个该动的旋钮是 `WAVE_DURATION`，不是敌人数。

### 16.15 状态修饰器：流血 / 霜缚 / 汲取（✅ 已实现 2026-11-08 第八轮）

#### 16.15.1 为什么是"词条"而不是"新武器"

ROADMAP 原计划写的是"可挂任意武器的修饰器"。落地时选了**被动卡**形态，
理由是它对"任意武器"的支持是**结构性的**，不是配置出来的：

| 方案 | 要改的地方 | 漏掉的风险 |
|---|---|---|
| 每把武器加 `can_bleed` 参数 | 11 把武器 + 6 个伤害来源（子弹 / 飞刀 / 闪电链 / 毒云 / 环绕刃 / 武器 AOE） | 以后每加一把武器都要记得接，漏了没人发现 |
| 在"受击方"统一处理（**采用**） | `EnemyBase._after_damage_taken()` 一处 | 无。所有伤害最终都会打到某个敌人身上 |

代价是**不能做"只让某把武器流血"**。判断：现阶段武器只有 11 把、每把的定位靠
伤害/射速/弹道区分，再叠一层"这把能流血那把不能"只会增加记忆负担，
收益小于"拿到血刃后所有武器都变强"的直观感。

#### 16.15.2 三个词条与数值

| 词条 | 效果 | Lv.1 | 每级 | 上限 | 设计意图 |
|---|---|---|---|---|---|
| **血刃** | 命中时概率使敌人流血 | 25% | +8% | 60% | 偏爱单发高伤（十字弩 / 散弹）。伤害按**触发那一下**折算，所以武器越重收益越高 |
| **霜缚** | 命中时概率减速 | 30% | +7% | 55% | 唯一改变"敌人到位时间"的词条。对付冲锋怪与围上来的近战 |
| **汲取** | 造成的伤害按比例转为生命 | 2% | +0.8% | 6% | 和「吸血獠牙」分工：那个奖励清场，这个奖励持续输出（打 Boss / 精英） |

**血刃的总伤**：`BLEED_DPS_RATIO 0.30 × BLEED_DURATION 2.5s = 一次命中的 0.75 倍`。
刻意压在 1 倍以下——超过 1 倍的话，流血会变成主要伤害来源，武器本身退化成"引火器"，
玩家的操作（瞄准、走近）就不再重要了。

#### 16.15.3 五个必须记下来的实现取舍

1. **流血走 `dot_damage()`，不走 `take_damage()`。**
   `take_damage` 每次都闪白 + 触发 0.05 秒受击冻帧。每 0.5 秒闪一次的话，
   "这怪在流血"和"我刚打中它"会完全混淆，而且冻帧会让流血的敌人看起来像卡住了。
   代价是绕过了子类覆写，所以**护甲（石像鬼）与登场无敌（Boss）用鸭子类型单独补上**：
   ```gdscript
   if "intro_invulnerable" in self and bool(get("intro_invulnerable")): return
   if "is_petrified" in self and bool(get("is_petrified")): return
   if "armor" in self: actual *= 1.0 - GameConfig.calculate_damage_reduction(float(get("armor")))
   ```
   注意必须用 `get()` 读：直接写标识符会让**基类整个解析失败**，连带 12 个子类一起炸。
   Boss 血条同理，用 `emit_signal("boss_hp_changed", ...)` 而不是 `boss_hp_changed.emit(...)`。

2. **状态 tick 放 `_process`，不放 `_physics_process`。**
   有一半敌人（`werewolf` / `zombie` / `skeleton_archer` / `vampire` / `vampire_mage` /
   `summoner` / `gargoyle` / `exploder` / `prince` / `lord`）自己覆写了 `_physics_process`，
   基类的物理帧对它们根本不执行。当前**没有任何子类覆写 `_process`**，所以这里是安全的——
   这条约束要一直守住，加新敌人时不要覆写 `_process`。

3. **急速改成"记时间 + 统一刷新"。**
   原来是 `move_speed = base × 1.18` 再 `await` 还原。一旦中间被减速改过，
   两个协程会互相覆盖成"永久变快"或"永久变慢"。
   现在所有修正都走唯一出口：
   ```gdscript
   move_speed = base × (急速 ? AFFIX_HASTE_MULT : 1) × (减速 ? slow_mult : 1)
   ```
   多来源减速**取最强的一个**而不是相乘——相乘会让两次 0.7 变成 0.49，等于控到死。

4. **弱流血既不叠层、也不续时间。**
   只做 `max(dps)` 但照样刷新时长的话，一把高频小弹能把十字弩打出来的高伤流血永久续着，
   等于免费获得不属于它的收益。现在 `dps < 当前值` 直接 return。

5. **同一敌人 0.3 秒内只判定一次。**
   高攻速武器每发都命中，不设冷却的话流血/减速会永久满覆盖：
   既是数值失控（流血常驻 = 常驻 75% 增伤），也是屏幕负担（20 只怪同时滴血）。

#### 16.15.4 顺带对齐：圆形弹的亮芯（ROADMAP 17.13 P2）

长条弹上一轮已经把亮芯占比从 0.16 提到 0.30，圆形弹（法球 / 圣光 / 火焰 / Boss 弹幕）
漏掉了。这次一起改：

| | 改前 | 改后 |
|---|---|---|
| 圆形弹亮芯占比 | 0.16 | **0.32** |
| 魔法书 / 圣光魔杖视觉直径 | 16×10 | **18×14** |
| 火焰喷射器 | 14×9 | **16×12** |

理由和长条弹完全相同：`thickness` 是**整条光晕**的直径，实心只占 16% 时屏幕上
真正"看得见"的部分不到 2px。**Boss 弹幕刻意没动**——它的判定半径独立设置在
`enemy_projectile`，视觉跟着放大而判定不变会制造反向错觉。

#### 16.15.5 与同类游戏对照

| 游戏 | 它的做法 | 我们 |
|---|---|---|
| Vampire Survivors | 属性升级（Might/Area/Speed…）直接乘算，没有"挂状态"的概念 | ❌ 不适用：VS 的爽点在数量，我们的房间更小、单只更重要，需要单点削弱手段 |
| Brotato | 有"燃烧 / 减速"等物品，但它们是**独立伤害源**（每秒结算固定值） | ⚠️ 部分参考：我们让流血按"触发伤害的比例"结算，避免后期固定的 DoT 数值完全过时 |
| 暗黑类 ARPG | 流血/中毒可叠层，层数越多伤害越高 | ❌ 不叠层：叠层需要 UI 显示层数，而我们没有敌人血条（Boss 除外），玩家读不出"它叠了几层" |

最后一条是这轮的判断核心：**没有可见的层数指示，就不要做叠加机制**。
玩家感知不到的复杂度，只会变成"某些怪莫名其妙就死了"。

### 16.16 局内目标事件：深渊猎物 / 受诅宝箱（✅ 已实现 2026-11-08 第九轮）

#### 16.16.1 为什么战斗房需要"钩子"

6~7 间房里只有 shop / treasure / rest / boss 有"进这间要干什么"的记忆点，
战斗房彼此无差别——玩家对房间的记忆是"又一间打怪的"。事件不做成新房间类型
（保持节奏不变），而是让其中一间（每层最多一间）多一个小目标。

| | 深渊猎物 hunt | 受诅宝箱 guard |
|---|---|---|
| 检验 | 边躲小怪边集火（输出） | 清场速度（且有"先杀守卫还是先打波次"的选择） |
| 目标 | 双词缀精英，事件血量 ×2.0 | 房间中央上锁宝箱 + 5 守卫（×1.3 血，金色） |
| 时限 | 20 秒（超时遁走，不追发奖励） | 无（守卫清不完=没开箱） |
| 奖励 | 30 银 + 80 XP | 25 银 + 60 XP |
| 触发 | 第 2 间战斗房起，35/40/45%（按层），每层一次 | 同左，二选一（hunt 权重 0.65） |

#### 16.16.2 实现取舍

1. **事件敌人不吃同屏上限**（`spawn_special_enemy` 不查 `_alive_enemies`）：
   上限的语义是"限制氛围怪"，猎物被上限卡住不出场、玩家对着倒计时干着急，
   是最差的一类 bug。
2. **事件不跨房**：`_enter_next_room` 开头无条件 `cancel()`，没做完就算失败，
   同时显式回收挂在 main 下的宝箱节点。允许"刷完事件立刻跑路白拿奖励"会退化成无脑最优解。
3. **守卫染金色 + 头顶「守卫」小字**：不打碎"普通怪怎么变金了"的疑问，
   玩家就不会把守卫当成优先目标，事件等于没发生。
4. **倒计时 HUD 是独立 event_label**，不复用 wave_label：波次编号和事件
   倒计时互相覆盖的话，两边的信息都会丢。
5. 概率判定在 `on_combat_room_entered`（main 在 wave_manager.start 之后调），
   事件敌人要挂当前场景，太早会挂错地方。首房虽延迟自动开战，也必须计数一次，
   否则“第 2 间战斗房起”会错成第 3 间。
6. **双词缀是"两个词缀"而不是"两次精英化"**：`elite_affix` 保留为主词缀并沿用
   逐层池；第二词缀从完整合法池（排除主词缀）选取，第 1 层也照样两个。
   统一加成（血/伤/银/经验/体型）每只只结算一次，第二词缀只提供自己的专属
   效果（例如血盾的盾量与破盾）。控制器复用 `EliteAffixController`：主槽位名
   保持 `AffixController`（兼容既有测试），第二槽位为 `AffixController2`，
   图标横向错开、光环半径不同；重复/非法 id 在装配时直接丢弃，不会长出第二个控制器。
   传给 `spawn_special_enemy` 的 id 超过两个时只取前两个不同的合法 id。
7. **事件奖励不吃深渊掉落倍率**：猎物/宝箱的固定奖励（30/25 银 + 80/60 XP）
   是"完成一个小目标"的定额回报，不随深渊等级放大。倍率只作用于敌人自身掉落
   （走 `loot_mult` 概率进位链）与层通关血晶。这样事件在任何深渊等级下都是
   同样可预期的选择，而不是"深渊越高越该刷事件"的另一种滚雪球。
8. **事件已结束后不再结算**：超时遁走/换房 `cancel()` 之后，猎物的死亡信号
   先断开、回调再按当前 `kind` 复核一次——淡出期间的 DoT、换房清场的击杀都
   不会补发奖励或补发第二次 `event_finished`。猎物被外部释放（清场/回收）时
   事件直接结束并清空 HUD，不会永久停在 hunt 倒计时。
9. **宝箱不与玩家重合**：玩家站在房间正中时，宝箱沿远离玩家的方向推开约 110px
   （再夹回房间内），否则两者互相遮挡，也读不出守卫圈的中心。
   宝箱回收幂等收敛在 `_end()`：守卫全部刷失败、`wave_manager` 缺失、
   换房 `cancel()`、换层 `on_floor_changed()` 都会走到它，不留一个永远打不开
   的箱子在场上（开箱成功那条路径把宝箱交还给自己的开箱动画）。
10. **开场信息写独立事件行，不用波次横幅**：事件与 “Wave N 开始” 可能同帧，
    共用 `wave_banner` 会互相覆盖。`_notify()` 走 `hud.set_event_status()`，
    并占住这一行约 1.2 秒（否则第一次 0.2 秒状态刷新就会把“守卫苏醒”顶成
    “守卫 ×5”，开场信息等于没显示）；随后倒计时/剩余守卫数继续更新同一行。
11. **事件标签与词缀图标分层**：双词缀图标在敌人头顶 y=-52，事件标签
    （「猎 物」「守 卫」）抬到 y=-80，两者不重叠。压在图标上等于两个信息都看不清。
12. **事件猎物固定吃事件血量、不吃 DPS 软缩放**：`spawn_special_enemy` 只叠加
    词缀倍率与 `ROOM_EVENT_HUNT_HP_MULT`（×2.0），不乘 `_soft_hp_scale`。
    这是刻意取舍——猎物是“限时输出检验”，如果血量跟着玩家理论 DPS 一起抬，
    检验的就不再是构筑强度而是软挂钩自己；守卫同理（×1.3 固定档）。

### 16.17 深渊阶梯（✅ 已实现 2026-11-08 第九轮）

通关结算界面新增「深入深渊 N」按钮：+1 等级后重开三层（血 +15%/级、
伤 +10%/级、掉落 +10%/级）。无尽雏形。

关键实现事实（容易踩错的几条）：

1. **GameConfig 不是 autoload，是纯静态类**。运行时等级必须用
   `static var abyss_level`——静态变量挂在脚本资源本身上，
   `reload_current_scene()` 重建 main 后依然在。普通 `var` 静态访问会
   Parse Error（测试当场就抓出来了）。
2. **深渊掉落乘进 `loot_mult` 而不是 round 进 `silver_value`**：
   掉落链有"小数部分概率进位"，直接 round base 值会复刻"1 银 ×1.1 永远 1"
   的老 bug。长期期望准确性交给既有管线。
3. **普通重开 / 回主菜单 = 放弃深渊**（归零）。深渊只在"连胜式继续"时保留，
   否则玩家想开一局正常难度却带着 ×3 难度开局，无从解释。归零统一走
   `GameConfig.abandon_abyss()`：普通重开、结算界面返回主菜单、暂停菜单返回
   主菜单、进入主菜单四条路径都收敛到它；「深入深渊」只做 +1 推进，绝不清零。
4. **Boss 也吃深渊倍率**。Boss 覆写 `_ready` 且不调 `super._ready()`，不走
   `EnemyBase` 的缩放链，所以血量/接触伤害/`loot_mult` 必须在
   `vampire_lord.gd` 里各自乘一次深渊倍率；`_recalc_damage()` 被狂暴/绝望阶段
   复用，深渊伤害倍率写在函数内部才不会在阶段切换时丢掉。
   血族亲王二阶段、Boss 弹幕、自爆者爆炸、法师法术这类“重算/非接触”伤害源统一走
   `EnemyBase._scaled_damage()`（波次 × 楼层 × 深渊），不再各自重算而漏掉倍率；
   `barrage_damage` 这类字段始终保存形态基础值，缩放只在命中结算时算一次，
   避免“生成时乘一次、命中时再乘一次”的二次乘法。
5. **通关界面的「深入深渊 N」百分比是下一轮总倍率**（等级 × 每级步进），
   不是这一次点击的增量；按钮文本写明“下一轮总计”，避免被读成在现有数值上
   再叠一层。

换层横幅与 HUD 层进度都带「渊N」前缀；胜利结算带 abyss_level；
`SaveManager.best_abyss` 记录**历史最深到达**的深渊等级（只增不减，
在玩家点「深入深渊」真正进入该级时写入，不是"通关过多少层"）。

## 附录 C: 实现校准值（以代码为准）

> 本节记录 A 阶段数值重构后**代码中实际生效的公式与实测结果**。若与正文表格冲突，以本节为准。

### C.1 敌人 HP 缩放（`scripts/core/game_config.gd`）

```gdscript
# 波次缩放：线性增长（不是复利）。每波 +12% 的**绝对**增量恒定
hp_mult = 1 + (wave - 1) * 0.12

# 楼层台阶：补回线性曲线的后期总量（旧版复利在第 12 波是 ×3.3，线性只有 ×2.32）
floor_hp = [1.0, 1.40, 1.85][floor - 1]

# 等级橡皮筋：玩家 3 级后每级 +3%，上限 ×2.0
level_scale = min(1 + max(level - 3, 0) * 0.03, 2.0)

# 最终 HP
max_hp = base_hp * hp_mult * level_scale * floor_hp * hp_scale   # hp_scale 用于召唤物/分裂体
```

设计意图：波次提供主斜率，等级缩放作为**防碾压阀门**，DPS 软因子修正"等级高但装备烂"的错配。
第 3 层末波等效倍率 ≈ ×4.29（旧版复利 ×4.98）。

### C.8 同屏上限与刷怪节奏（2026-11-08 新增）

```gdscript
# 同屏存活上限（按层）。这是"实际压力"的真正闸门，比刷新间隔更重要
ENEMY_ALIVE_CAP_BY_FLOOR = [16, 22, 28]

# 软上限：距上限 ≤4 只时，补怪间隔 ×2（避免"刚清出的缝立刻被填上"）
if alive >= cap - 4: interval *= 2.0

# 刷新间隔（仅在未满员时才有意义）
interval = max(1.3 - (wave - 1) * 0.04, 0.4)
每批数量   = 2 + wave / 4   （上限 5）
```

| 2 | 22 | ≈ 4.2 万 px² |
| 3 | 28 | ≈ 3.3 万 px² |

> **不要照抄同类项目的 200/300**：那是"整张大地图 + 全屏 AOE 清场"的量级。
> 这个游戏是 1280×720 的封闭小房间 + 单体投射物为主，按面积折算 16 只的密度已高于
> 同类后期。详细对标见 §16.14。

### D.4 UI 字体与图标规范（2026-11-08 修正）

**界面文字一律不用 emoji。** 项目主字体是 `NotoSansCJKsc-Regular.otf`，不含 emoji 字形，
系统 fallback 也不是所有码位都覆盖。实测 `🔄 🚫 ⏭ 💰 🎲` 在 Button 上全部渲染成
**蓝色方块**（颜色取自按钮的 font_color），而 `🩸 🕯` 在 Label 上却能显示——
同一份字体、同样的文本，控件不同结果就不同。这种不一致没法靠推断保证，
只能约定"不用"。

| 位置 | 旧写法 | 现写法 |
|---|---|---|
| 三选一 footer | `🔄 重抽 (3)` / `🚫 放逐` / `⏭ 跳过 (+💰15)` | `重抽 (3)` / `放逐` / `跳过 (+15 银)` |
| HUD 银币 | `💰 150` | `银币 150` |
| 商店标题 / 按钮 | `🏪 银币商店` / `🎲 重抽 (10 💰)` | `银 币 商 店` / `重抽 (10 银)` |
| 祭坛卡片 | `🕯 安息` / `🩸 缔结契约` | `安　息` / `缔 结 契 约` |
| 掉落物图标 | `❤️ ⚔️ 🧲` | 中文字 `血 / 狂 / 磁` + 名称标签 |

替代方案（按优先级）：
1. **彩色贴图**（`TextureManager` / `ProjectileVisuals`）—— 卡片图标走这条，已验证可靠；
2. **中文字**（掉落物用单字 + 名称，形成双编码）；
3. **纯文字**，靠字号/颜色/边框做层级。

`→` `×` `·` `（）` 这类中西文通用符号可以放心用（CJK 字体都有），
截图中 `×1.00 → ×1.15` 渲染正常。

**验收方式**：改任何 UI 文本后必须跑一次带窗口的截图脚本。
无头测试全绿也不能证明文字没变成方块——这是唯一能抓住这类问题的办法。
